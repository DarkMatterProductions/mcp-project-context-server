# Gemini CLI / AI Studio

## Overview

The [Gemini CLI](https://github.com/google-gemini/gemini-cli) is Google's open-source command-line AI tool powered by Gemini models. It supports MCP servers via **STDIO transport**. [Google AI Studio](https://aistudio.google.com) is the web-based counterpart for prototyping; the Gemini CLI is the recommended interface for local MCP server integration.

---

## Prerequisites

- [Gemini CLI](https://github.com/google-gemini/gemini-cli) installed:
  ```bash
  npm install -g @google/gemini-cli
  ```
- Python 3.10+ and `pip`
- A Google API key from [aistudio.google.com/app/apikey](https://aistudio.google.com/app/apikey)

---

## Installation

```bash
# Base — can use any embedding provider
pip install mcp-project-context-server

# With Google Gemini embeddings (pairs naturally with Gemini CLI)
pip install "mcp-project-context-server[google]"

# With Vertex AI embeddings (GCP-native alternative)
pip install "mcp-project-context-server[google-vertex]"
```

Verify:
```bash
which project-context-server
```

## Configuration

The Gemini CLI stores MCP server configuration in its settings file at:

| OS | Path |
|---|---|
| Linux / macOS | `~/.gemini/settings.json` |
| Windows | `%USERPROFILE%\.gemini\settings.json` |

Add a `mcpServers` block (the same format used by other Gemini tooling):

---

### Example 1 — Google Gemini API Embeddings (recommended pairing)

Using `EMBED_PROVIDER=google` means your embeddings are generated by the same Google infrastructure that powers the Gemini models in the CLI. This avoids cross-provider latency and uses a single API key.

**~/.gemini/settings.json:**
```json
{
  "mcpServers": {
    "project-context": {
      "command": "/usr/local/bin/project-context-server",
      "env": {
        "EMBED_PROVIDER": "google",
        "GOOGLE_API_KEY": "AIzaXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX",
        "GOOGLE_EMBED_MODEL": "text-embedding-004",
        "VECTOR_STORE_PROVIDER": "chroma-local",
        "REPO_PROVIDER": "local"
      }
    }
  }
}
```

Get your API key at [aistudio.google.com/app/apikey](https://aistudio.google.com/app/apikey). The same key is used for both the Gemini CLI (`GEMINI_API_KEY`) and the embedding provider (`GOOGLE_API_KEY`).

---

### Example 2 — Ollama (fully local, no API key)

```json
{
  "mcpServers": {
    "project-context": {
      "command": "/usr/local/bin/project-context-server",
      "env": {
        "EMBED_PROVIDER": "ollama",
        "OLLAMA_BASE_URL": "http://localhost:11434",
        "OLLAMA_EMBED_MODEL": "nomic-embed-text",
        "VECTOR_STORE_PROVIDER": "chroma-local",
        "REPO_PROVIDER": "local"
      }
    }
  }
}
```

---

### Example 3 — Vertex AI Embeddings (GCP-native)

Useful if you're already using Application Default Credentials (ADC) for Gemini on Vertex AI:

```json
{
  "mcpServers": {
    "project-context": {
      "command": "/usr/local/bin/project-context-server",
      "env": {
        "EMBED_PROVIDER": "google-vertex",
        "GOOGLE_CLOUD_PROJECT": "my-gcp-project",
        "GOOGLE_CLOUD_LOCATION": "us-central1",
        "VERTEX_EMBED_MODEL": "text-embedding-005",
        "VECTOR_STORE_PROVIDER": "chroma-local",
        "REPO_PROVIDER": "local"
      }
    }
  }
}
```

Authenticate locally:
```bash
gcloud auth application-default login
```

## Embedding Provider Options

| Provider | `EMBED_PROVIDER` | Key variable | Notes |
|---|---|---|---|
| Google Gemini API | `google` | `GOOGLE_API_KEY` | Same API key as Gemini CLI — natural pairing |
| Vertex AI | `google-vertex` | `GOOGLE_CLOUD_PROJECT` | GCP ADC; no separate API key |
| Ollama | `ollama` | `OLLAMA_EMBED_MODEL` | Local, free, no Google account needed |
| Voyage AI | `voyage` | `VOYAGE_API_KEY` | Best code retrieval quality |
| OpenAI | `openai` | `OPENAI_API_KEY` | Cross-platform |
| Cohere | `cohere` | `COHERE_API_KEY` | Multilingual |

## Vector Store Options

### `chroma-local` (default)

Zero-config local persistence. Suitable for individual developer use.

```json
"VECTOR_STORE_PROVIDER": "chroma-local"
```

### `pgvector`

For shared or persistent team indexes:

```json
"VECTOR_STORE_PROVIDER": "pgvector",
"PGVECTOR_CONNECTION_STRING": "postgresql://user:***@host:5432/dbname"
```

Requires: `pip install "mcp-project-context-server[pgvector]"`

---

## Repository Provider Options

For local filesystem projects (most common Gemini CLI use case), the default `local` provider is correct. `project_path` should be an absolute filesystem path.

To index GitHub repositories directly:

```json
"REPO_PROVIDER": "github",
"GITHUB_TOKEN": "ghp_xx...xxxx"
```

## Verification / Quick Test

Start a Gemini CLI session:
```bash
gemini
```

Ask:
```
Index /path/to/my-project and give me a high-level overview of the codebase.
```

The CLI will invoke `index_project_context` via MCP, then answer using the indexed content. On subsequent sessions the index is already populated, so queries run immediately.

**Troubleshooting:**
- Run `gemini --mcp-debug` to see MCP server startup logs
- Confirm `project-context-server` is in your `PATH` and the path in `settings.json` is absolute
- If using `EMBED_PROVIDER=google`, confirm your `GOOGLE_API_KEY` has the **Generative Language API** enabled in your Google Cloud project
